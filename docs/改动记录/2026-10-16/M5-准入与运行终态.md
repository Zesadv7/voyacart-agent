# M5：共享准入与可重放运行终态

日期：2026-10-16（Asia/Shanghai）。基线 M4 `6b41289`，共享半开探测提交 `993fa69`。本地实现，无推送、部署或付费调用。

## 需求和实现

- `app/application/run_admission.py` 提供即时拒绝的进程级 gate，legacy inline、AGUI producer 和同进程 worker 共享。默认 `RUN_MAX_ACTIVE=8`，名额覆盖 reserve 到实际协程结束；首次调度前取消、reserve 失败也释放。计数是 gate acquire 次数，不冒充 HTTP 唯一请求数。多进程总上限为各进程上限之和。
- legacy/AGUI 队列入口共用构造容量 `AGUI_QUEUE_MAX_PENDING=200`，legacy 也传上限。队列启用却缺实例、Redis 失败/响应丢失时返回 503 和 Retry-After，不启动 API 本地执行。结果未知使用 `QUEUE_ACCEPTANCE_UNKNOWN`，客户端保留原请求键查询/重试。配置过队列但客户端初始化失败也失败关闭。健康检查不把未知 depth 当 0。
- `AGUIRuntime.start` 在 reserve 前取得名额，但 journal 同键重放先于准入；满载拒绝不创建 phantom run。`AGUIJournal.existing` 保留原指纹/买家/会话校验，不重签旧 run 的目录。
- 默认 `RUN_TIMEOUT_SECONDS=300`。AGUI 独立 watchdog 持久化 `RUN_DEADLINE_EXCEEDED`，即使下游吞取消也不能让 journal 一直 running；实际任务未结束前仍占名额且 persistence guard 已失效。legacy inline/worker 同样有期限和 guard。此处无法强杀不合作的协程或中止已发出的外部副作用；它仍占名额，也可能拖长优雅退出，进程终止期限需M6验证。保留 at-least-once 和原交易幂等约束。
- 默认 `QUEUE_MAX_AGE_SECONDS=900` 使用 Redis 服务器时间，仅限制等待/重试的执行资格。恢复循环每 5 秒最多取 100 项到期任务；legacy-only queue 也接恢复队列。AGUI `fail_unstarted` 原子写 RUN_STARTED/快照/错误终态，重试可重复；已有运行/较新会话不被覆盖，未执行任务不写 `agui_run_catalog`。
- queue terminal、journal terminal 和交易业务成功分别判断。队列 done 是投递收口，journal 仍可 interrupted/error；没有 exactly-once 宣称。

关键代码：`app/application/agent_runtime.py`、`app/infrastructure/ag_ui_journal.py`、`app/presentation/server.py`、`app/presentation/ag_ui.py`、`app/worker.py`、`app/composition.py`、`app/infrastructure/settings.py`。

## 启用、局限和回退

新配置是保守可调边界，8/200/300/900 不是实测生产最优值。worker concurrency 必须正且不超过同进程 RUN_MAX_ACTIVE；容量短窗仅 B=2 合成150ms Agent，不证明生产负载或收益。所有运行受约束，不改变模型策略、目录或候选数据。

旧 Redis 带 TTL 的历史任务仍需停写窗口、dry-run 和受控 PERSIST/backfill；无法恢复已遗失身份。历史终态/墓碑永久保留，准入有界不等于历史存储恒定。共享 breaker 需要协调升级，混跑旧进程不能保证新原子协议。

回退先停写并排空/明确中断在途，保存一致代码、Redis AOF、SQLite和归档，再恢复匹配版本；不要删除状态/墓碑或仅回旧代码后声称保留合同仍成立。真实部署、持久化容器恢复、完整真实模型与真实浏览器仍分别是外部门禁。
