## 需求和具体变更

关键源码：`docker/docker-compose.yaml`、`docker/docker-compose.scale.yaml`、`Dockerfile`、`.env.example`、`tests/test_compose_delivery.py`。

### 网络与环境继承

- 普通编排仅发布 `127.0.0.1:8000:8000` 和 `127.0.0.1:5173:80`；Redis/Qdrant 不再发布任何宿主端口，worker 从未发布端口。Compose 容器网络中的服务仍可互访，这不是租户隔离或外部防火墙配置。
- scale 保留 API、Redis、Qdrant 的 `ports: !reset []`，只有 nginx 发布 `127.0.0.1:${VOYACART_SCALE_PORT:-8080}:80`；mock profile 的模型服务不发布宿主端口。即使以后基础文件增加端口，scale 的重置仍阻止继承。要求 Compose >=2.24.4；本次使用已有官方独立二进制 `/tmp/voyacart-compose`，实测版本 2.40.3。
- 基础 `x-agent-options: &agent-options` 通过 YAML `<<: *agent-options` 进入普通 app、worker。scale api `extends app`，worker 与 automation-worker 都 `extends worker`；Compose 按 environment 映射键继承基础配置，再叠加 `x-scale-options`。测试核验的是官方 Compose 最终 JSON，不只检查 YAML 文本。
- API 和所有 worker 统一透传以下默认值，宿主显式值同样到达各进程：

| 配置 | Compose 默认 | 语义 |
|---|---|---|
| `PUBLIC_DEPLOYMENT` | `0` | 仅私有演示；`1` 启用既有启动校验，不创建 TLS 或公网监听 |
| `CORS_ORIGINS` | `http://localhost:5173,http://127.0.0.1:5173` | 可显式替换；公网要求明确 HTTPS Origin |
| `HTTP_MAX_REQUEST_BYTES` | `1048576` | 已有 HTTP body 护栏 |
| `HTTP_BODY_TIMEOUT_SECONDS` | `30` | 已有 body 读取期限 |
| `HTTP_REQUESTS_PER_MINUTE` | `0` | 私有演示不启用该速率限制；公网必须正值，按 API 进程计 |
| `RUN_MAX_ACTIVE` | `8` | 进程级准入；多个副本的总量相加 |
| `RUN_TIMEOUT_SECONDS` | `300` | 整轮期限；不等于强杀协程或撤回外部副作用 |
| `QUEUE_MAX_AGE_SECONDS` | `900` | 等待/重试执行资格期限 |
| `AGUI_QUEUE_MAX_PENDING` | `200` | legacy intents 和 AG-UI 共同服从的队列构造上限 |

- AGUI 入队、增量合并、automation 模式和顺序断言亦从基础 anchor 透传。普通默认分别为 `0 / 0 / embedded / 0`；scale 保持原来的 `1 / 50 / external / 1`，其中 automation、顺序断言是 scale 固定覆盖。scale 仍固定开启共享 breaker/Redis 队列。`AGUI_QUEUE_MAX_PENDING` 不再在 scale 重复声明，避免与基础 M5 合同漂移。
- `IDENTITY_HMAC_SECRET`、`MODEL_MASTER_KEY`、LLM 可选 thinking/context、Langfuse 及回退模型的显式空值语义保留；没有把服务端 token/密钥变成前端 `VITE_*`。本次只测试合成占位字符串，未读取、打印或生成真实凭据。

### 健康检查

普通 app 增加现有 Python `urllib.request` 的 `http://127.0.0.1:8000/health` 探针：请求 timeout 3s、检查 timeout 4s、间隔 5s、重试 60 次、启动宽限 10s。scale api 继承同一探针，删除原来的重复定义。普通 frontend 改为等待 app `service_healthy`，scale nginx 原有的 api `service_healthy` 保持。

`/health` 检查已构造的主/交易 SQLite、Redis、队列 depth 和提示词注册等现有状态；不是所有独立 SQLite、worker 消费能力、真实模型、Qdrant 全部索引和业务效果的就绪证明。Redis 仍用镜像自带 `redis-cli ping`；Qdrant 依然只要求 `service_started`，检索允许降级，没有假定其镜像提供 curl/wget。`depends_on` 是启动顺序约束，也不保证依赖在运行期间持续健康。

### 资源、日志与持久队列

保护性默认值未经容器容量压测，不是推荐生产容量或吞吐承诺。CPU、内存、PID 限额以服务级字段声明；不是仅在 Swarm 使用的配置。

| 单容器 | CPU 上限 | 内存上限 | PID 上限 |
|---|---:|---:|---:|
| app / api / worker / automation-worker / Qdrant | 2 | 2 GiB | 256 |
| Redis | 1 | 512 MiB | 64 |
| frontend / nginx | 0.5 | 128 MiB | 64 |
| mock-llm | 1 | 256 MiB | 64 |

- 所有服务使用 `json-file`，每文件 `10m`、保留 `3` 份。基础 `x-runtime-limits` 由 app/worker/Redis/Qdrant/frontend 合并，scale 业务服务继承，nginx/mock 使用同样的轮转配置及其小服务限额。
- Redis 保留 AOF `appendonly yes / appendfsync always`，增加 `maxmemory 256mb / maxmemory-policy noeviction`。到内存边界时拒绝需分配的写入，不能靠逐出缓存连带删除任务身份；缓存与队列仍共享实例，内存压力可能使业务请求失败。maxmemory 不涵盖全部 AOF/进程开销，512 MiB 也不保证不会 OOM，仍须监控并实测。
- 日志轮转不限制 SQLite、Redis AOF、永久队列终态/墓碑、Qdrant 卷或 Docker 构建缓存；仍需磁盘监控、受控归档和一致备份。副本数增加时资源与进程级运行总预算相加。没有声称形成集群总额、完成容量规划或更改宿主防火墙。

## 启用与回退

- 在合成/私有环境先执行配置解析，再在具备 Docker 的验收机器构建和检查实际健康状态。不要把带真实密钥的完整 `docker compose config` 输出保存到证据、终端共享或日志；公开交付仅使用白名单投影。
- 普通入口使用 `localhost:5173`/`127.0.0.1:5173`，scale 使用 loopback 8080 或显式端口。需要调试 Redis/Qdrant 时另用明确的回环 override；不要恢复无 host IP 的端口映射。资源调整同样通过经检查的 override，环境示例中的描述不是自动调参变量。
- 公开部署仍需单独安排 TLS、身份/密钥、HTTPS Origin、正 token 预算和 HTTP 速率及实际门禁。本次不改变监听范围来协助公网发布。
- 配置回退先停写/排空或明确中断在途，保留一致版本代码、SQLite、原模型主密钥、Redis AOF 与归档。不要删卷；不要将旧的全接口端口暴露直接带回。M5 保留合同需要协调版本恢复；单纯回退镜像不证明数据兼容。
