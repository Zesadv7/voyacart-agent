# M6：停写恢复组快照工具

日期：2026-10-16（Asia/Shanghai）。实现基线：`563132d`，即 M5 集成记录完成后。此功能尚未单独提交；最终关联版本由主 M6 交付索引补充。

## 需求与实际边界

为本机合成演示增加显式停写后的多 SQLite、Redis 持久目录、目录输入及模型主密钥恢复工具。工具不能证明调用者已经停止写入：入口、所有 API/worker/automation-worker、维护脚本必须统一停写；复制 Redis 持久目录前还必须停止专用 Redis。逐库 SQLite backup API 的一致性不等于在线跨库/Redis 原子快照。

本切片只有临时合成目录上的合同测试。没有读取真实 DATA_DIR、真实 `.env` 或真实主密钥，没有连接既有 Redis，没有执行 Docker、网络模型调用、安装、远程发布或生产迁移。真实 Redis 进程、HTTP、业务幂等和索引重建由 M6 隔离恢复演练单独记录；不能以本切片的 Redis 字节复制测试替代引擎恢复证据。

## 具体实现

源码：[state_snapshot.py](../../../scripts/ops/state_snapshot.py)、[包入口](../../../scripts/ops/__init__.py)。测试：[test_state_snapshot.py](../../../tests/test_state_snapshot.py)。

- `backup(data_dir, output, *, quiesced, redis_dir=None, redis_stopped=False, catalog_paths=None, fingerprint_paths=None, database_url=None, include_model_key=False, model_key_reference=None)`：只处理显式来源与新目录，返回私有清单。
- `verify(snapshot, *, external_model_key_file=None, model_key_reference=None, expected_fingerprints=None)`：验证所有已列文件、目录、SQLite integrity/foreign-key/表聚合及主密钥连续性。
- `restore(snapshot, target, *, redis_target=None, catalog_target=None, external_model_key_file=None, model_key_reference=None, expected_fingerprints=None)`：先完整校验，再复制到互不重叠的新目录，不启动服务、不迁移、不重建索引。
- `fingerprint_files({别名: 路径})`：显式公共源码/配置/锁文件内容指纹；目录指纹包括相对名称与内容，排除解释器缓存 `__pycache__`、`.pyc`、`.pyo`，拒绝 `.env`/`.secrets` 输入和链接。`expected_fingerprints` 是别名到摘要的映射，不是文件路径。
- `summary(manifest)`：只返回可公开的聚合计数、组件状态与边界标识，不能把完整 manifest 当成公共日志。

固定 SQLite 清单含 13 个支持位置：`voyacart.db`、`ag_ui_runs.db`、`queue_archive.db`、`context_evidence.db`、`buyer_memory.db`、`capabilities.db`、`buyer_skills.db`、`shopping_forms.db`、`buyer_favorites.db`、`models.sqlite3`、`prompts/registry.sqlite3`、`sessions/session-state.sqlite3`、`trade.db`。已提交的 WAL 通过只读源连接和 `Connection.backup` 合入独立输出库；不直接复制 WAL/SHM，输出库改用 DELETE journal。

附加状态支持 `queue_maintenance_cursors.json`、`orders.json`、preferences/sessions 下的 JSON、conversations 下的 JSONL。未产生的固定状态列为 absent，未知文件、孤立 SQLite sidecar、固定库路径为目录、外置数据库 URL 均拒绝。若传入 DATABASE_URL，仅支持 `file` 或 DATA_DIR 内的 `voyacart.db`/`trade.db`。调用者必须准确传入真实数据库配置；工具不会读取环境变量来猜测。尚未迁移的 orders.json 只原样保留，不表示应用允许继续处理旧订单。

`qdrant`、`qdrant_kb`、`local_embedding` 明确排除并标记重建。`catalog_paths` 按安全别名冻结输入文件/目录，恢复至 `catalog_target/<别名>`；冻结公共源码、配置、知识及锁文件时使用 `fingerprint_paths`，备份前后比较一致性。恢复必须显式传入与清单完全一致的指纹映射，防止忽略已固定项。未提供目录/配置输入时，只能称为组件状态备份，summary 会明确报告未绑定，不能声称完整可启动恢复组。

Redis 以停止后的专用持久目录为单位复制全部普通文件与子目录，包括 Redis 7 multipart AOF 的 manifest/base/incremental，以及 RDB 和空子目录；不猜测单个 AOF 文件是否足够，不连接在线服务器。工具不检查 Redis 引擎格式或队列语义，须在新隔离实例中另行验收。

## 密钥与隐私

- 默认不导出主密钥。存在 models.sqlite3 时，必须显式选择保留原本地 key 或声明外部 key 的非敏感版本标签；没有模型库时拒绝单独导出/引用 key。
- 本轮所有 key 都是测试临时生成的 Fernet fixture。key 文件不记录大小、内容或摘要；工具验证已有 `model_secrets` 和 `model_validation_tickets` 非空密文能用原 key 解密，不返回任何明文。
- 缺 key、错 key、格式错误、孤立 key、没有任何可验证加密记录的模型库均 fail-closed；后一种库无法用解密证明 key 连续性，暂不支持，不自动生成替代 key。
- 外部模式 backup 仅保存版本引用。verify 无 key 时可验证介质，`model_key_verified=false`；restore 要求外部原 key 文件和匹配引用并实际验证解密。外部 key 不复制进恢复目录，应用启动仍须用原外部密钥机制提供它。
- 输出目录 0700、文件 0600。完整 manifest 包含恢复所需的相对文件名、表名、聚合计数与文件摘要，是私有恢复材料；名称仍可能含业务标识，不能随证据包公开。CLI 只打印聚合摘要或脱敏错误，不打印原路径、表内容、密钥引用、ciphertext 或密钥摘要。
- manifest 没有签名：能检测缺失、额外文件、普通篡改和不一致，不能证明攻击者未同时改写清单与内容，不应宣称加密归档、来源认证或抗恶意管理员篡改。

## 启用与回滚

先停止所有写入者及需要保存的 Redis，再使用现有虚拟环境执行。例子中的目录必须是操作者确认的隔离来源，不能照抄替换为在线生产目录：

```bash
.venv/bin/python -m scripts.ops.state_snapshot backup \
  --data-dir <已停写合成目录> --output <全新快照目录> --quiesced \
  --database-url file \
  --redis-dir <已停止的专用Redis持久目录> --redis-stopped \
  --catalog runtime=<冻结目录输入> \
  --fingerprint source=app --fingerprint configs=configs --fingerprint lock=uv.lock \
  --include-model-key
.venv/bin/python -m scripts.ops.state_snapshot verify --snapshot <快照目录>
.venv/bin/python -m scripts.ops.state_snapshot restore \
  --snapshot <快照目录> --target <新DATA_DIR> \
  --redis-target <新Redis目录> --catalog-target <新目录输入目录> \
  --fingerprint source=app --fingerprint configs=configs --fingerprint lock=uv.lock
```

`--include-model-key` 是显式敏感材料保留选项，本轮只验证合成 fixture。真实使用前须独立确认权限、备份存放与访问控制。外部模式改用 `--model-key-reference <非敏感版本标签>`，恢复另加 `--external-model-key-file <原key文件>` 和同一引用；不要把 key 值放在参数或版本标签里。

备份开始后写 incomplete 标记，所有文件成功后才原子发布完整清单；失败目录保留现场且不可作为完整快照。恢复各目标带 incomplete 标记，全部校验完成才移除；失败后不得原地重试覆盖，应另选新目录并检查原因。禁止符号/硬链接、路径穿越、特殊文件、源目标重叠及非空目标。原状态和原快照不删除、不改写；回退工具只需回到原目录/原版本的既有受控启动流程，不能把新旧数据库随意混配成已经验证的业务回滚。
