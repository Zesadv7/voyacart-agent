# M4：会话候选与比较的 SQLite 持久层

日期：2026-10-16 Asia/Shanghai（执行时间为 2026-10-15 UTC）。

## 需求与范围

为主动保留的商品规格提供跨搜索、刷新和会话恢复的独立候选集合；比较只保存候选 ID，不复制第二套报价。原始 run、收藏、确认及订单均不迁移或重写。本记录覆盖持久层实现与定向离线回归；HTTP、应用装配、前端、浏览器及真实外部链路由 M4 总记录分别报告，不把本报告当作整个功能验收。

## 具体变更

- 新增 `CandidateWorkspaceStore`，复用 AGUIJournal 的同库连接及 `BEGIN IMMEDIATE` 事务，独立创建候选工作区、候选、成功请求三张表。
- 公开方法为 `list`、`add`、`remove`、`compare`；`get_candidate` 仅供应用服务读取内部目录绑定及集合版本。公开集合不包含 identity/terms hash、generation 或原始内部来源数据。
- 所有读写校验 journal 会话归属；写事务再次核对来源 run、候选和工作区 owner。未知会话 GET 不创建工作区或绑定关系。
- 来源只读指定 run 的已提交 `projection.state.products`；不回读工具正文、会话最新卡片或其他 run，不接受客户端快照。校验完整 ProductCard、明确 SKU、有限金额、严格库存及可选展示字段；执行 M2/M3 公开白名单并收紧嵌套展示字段。
- 一个 `(session_id, product_id, sku_id)` 对应一个候选；随机 UUID 删除后不复用。同商品不同 SKU 独立保留，选非默认 SKU 时同时更新展示与来源金额/币种并移除另一规格的到手价。默认 SKU 仅保留币种、金额恒等式均有效的历史到手价。
- 每会话最多 30 个候选，比较最多三个不同且存在的候选，并保留顺序。删除候选和清理比较在同一事务完成；同项保留和相同比较为 no-op，不覆盖旧快照/时间，也不增加 revision。
- 成功请求的版本化 canonical hash 包含 action、路径目标、来源/有序比较 IDs 和 expected_revision。相同 request_id 的成功响应先于来源/版本校验重放；改载荷或跨操作重用相同 key 返回冲突。失败不记为成功。
- 来源读取、候选变化、revision 和完整成功响应只进行一次原子提交；没有请求 TTL 清理。旧成功响应可以带旧版本，调用者必须按集合 revision 单调合并，不能借重放恢复已删除候选。
- 目录来源读取 run 固定的 snapshot binding，既有未绑定 run 不用当前目录补签。复用 M3 `catalog_bindings`，用公开卡片实际身份字段、所选 SKU 规格与标题/配送/产地重建 identity/terms hash；继承旧卡或事实不匹配时只保存 unknown 历史。缺失/畸形绑定或不匹配 product/version/active 拒绝。可信 generation 原样留在私有绑定，供核验服务后续比较。

## 启用、增长与回滚

- 初始化只增加新表。应用装配需初始化 store，journal 必须提供 run 固定目录 snapshot 表；实际装配属于 M4 API 集成。
- 成功请求记录永久保留本次完整结果，大小随成功操作数增长。第一期没有自动清理；今后任何保留期必须重新定义幂等恢复范围，不能直接删记录后仍声称永久幂等。
- 部署前按既有方式备份同库数据。回滚应用可保留新增表，禁用候选路由/UI 即可；不要删除候选/请求表，也不要重写旧 run 或目录身份。
- 所有候选都是历史展示，不是报价预留。unknown 来源需重新查询；bound 也必须经当前目录核验及既有 prepare/resolve 确认。真实商家、实时库存和实际支付均不在本实现声明范围。
