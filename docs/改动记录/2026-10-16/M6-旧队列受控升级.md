# M6：旧队列身份受控升级

2026-10-16（Asia/Shanghai）。基线 M5 `563132d`。不修改在线运行逻辑；只提供由操作员在停写窗口显式运行的维护工具，没有连接或迁移真实用户 Redis。

## 需求与变更

M5 新任务不再给非终态身份设置 TTL，旧存量仍可能在升级前后过期。`scripts/ops/queue_upgrade.py` 默认 dry-run，按两条 Stream 有界扫描；`--apply --quiesced` 才写入。每个消息必须仍有对应身份且 payload fingerprint 匹配，才允许补全原始 task、按 Stream 服务器时间补 accepted/deadline、去除 TTL 并建立待运行期限索引。已有期限不延长；running 不加入排队期限索引。

写入 Lua 同时核对原始状态与 Stream payload 未变，提前检查索引类型。身份丢失、语义冲突、坏状态或 CAS 竞争失败都保留原数据并阻塞，不从当前请求猜测重建，不新增 Stream 消息，不执行任务，不删除数据。报告仅含 stream/message ID、计数和固定原因，不含买家/查询/task payload；Redis URI 不输出。

先用每流最多1001项的有界完整来源清单核对task来源；任一流超过1000项或存在坏payload就拒绝迁移，不能只看当前分页就选最早消息。有status.stream/message_id时严格匹配；缺绑定时必须在两流中只有一个来源。inventory前后及Lua内绑定 length、last-generated-id、entries-added，拒绝净新增及等长替换。

实际处理每流每批最多 limit（默认200，最大1000）项。`next_cursors` 仅续同阶段；dry-run 游标不能用于 apply，apply 从流起点重新扫描。blocked报告禁止续游标，必须处理阻塞后从头重扫，不能用后页通过掩盖前页失败。END 只表示该流扫描结束，`scan_complete` 仅说明此次两条流遍历完，不证明孤立状态键、历史已遗失身份或全部业务状态完整。

## 升级流程与限制

1. 停止入口及全部旧 API、worker、automation-worker/维护写入者，禁止新旧共享 breaker 协议混跑；确认已在统一停写窗口保留 SQLite、Redis AOF、目录和原主密钥的一致快照。
2. 明确指定自有 REDIS_URL，dry-run 从两条流起点遍历。短 TTL 可能在扫描时自然消失，此时明确报缺身份，不能忽略或重跑为成功。大存量必须安排足够早的维护窗口；本工具不暂停 Redis 时钟。
3. 审阅 blocked、terminal_with_ttl_unchanged 及范围。清楚接受新 QUEUE_MAX_AGE_SECONDS 对旧待运行消息可能已过期的后果，正式迁移真实数据需操作员授权。
4. `--apply --quiesced` 从头遍历，记录每批报告；停写是操作员声明，不是工具证明。前面批次成功、后面批次失败属于部分迁移，不能把异常当回滚，保留原快照和报告再处理。
5. 新版本全体进程就绪后复核过期任务可查终态、重投无额外副作用，再开放入口。任何身份缺失/不一致阻塞开放；不要删 Redis 键/数据卷绕过。

旧终态保持不变；其剩余 TTL 会单列计数。这一工具不承诺修复全部历史幂等缺口，不对已消失的终态身份做推断。旧版本回滚会重新引入 TTL 和共享 breaker 非原子行为，因此不能只切旧镜像就宣称仍保留 M5 保证。恢复旧快照会丢失快照之后的写入，需单独决定；本轮只验证合成快照回退，不做真实回退。

共享 breaker 的旧 JSON 在新 Lua 访问时兼容读取，但旧进程可无条件删键/读改写。必须协调全体进程升级，保留原 Redis；无需清键。回滚同样协调重启，并明确失去单探针/旧回调 fence 保证。
