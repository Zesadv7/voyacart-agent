## 需求与边界

在新建的合成目录中实际验证多 SQLite、Redis 队列持久状态、原模型主密钥、冻结目录与派生索引构成的同组恢复。统一停止所有应用写入者和专用 Redis 后备份，再恢复到另一套新目录；不接触真实运行数据、实际用户、付费模型或真实支付。

实现：[scripts/ops/mock_recovery.py](../../../scripts/ops/mock_recovery.py)，辅助合同：[tests/test_mock_recovery.py](../../../tests/test_mock_recovery.py)。备份/恢复复用 `scripts.ops.state_snapshot`；HTTP 进程、SSE 分帧和净化环境复用 M1/M2 `scripts.ci.mock_smoke`、`offline_env`，队列执行复用正式 `AGUIRuntime`、`RedisStreamTaskQueue` 与 `app.worker.execute_ag_ui_task`。

## 实际演练顺序

1. 用固定、公开、仅测试的合成 HMAC 身份与 Fernet 主密钥，启动真实回环 socket mock 模型/API。环境只继承 PATH/语言等必要键，不继承真实网关、代理、凭据或遥测。工作树有 `.env` 时直接拒绝，避免现有 settings 对 Langfuse 文件的显式读取；不会读取或修改该文件。
2. 真实 HTTP 完成检索，保存两个 SKU 候选与比较，prepare 意向订单，测试夹具明确批准，得到唯一订单及一次库存扣减。只创建未支付 `purchase_intent`。
3. 停 API，使用已有存储接口补齐合成收藏、个人技能、未发布 capability 草稿、已提交表单、上下文证据、偏好事实及 mock 向量；另通过真实交易服务创建 1 秒有效期的确认用于恢复后的过期检查。
4. 新开专用回环 Redis 7.4.2，开启 multipart AOF、`appendfsync always`、`noeviction`。正式 queue/runtime/helper 完成一个运行并归档；第二个 accepted queued 运行已由 consumer 领取进入真实 PEL，但未进入 handler。额外 journal owner 租约用于验证旧 owner 不可恢复续写。
5. 关闭全部 runtime，再优雅停止 Redis。此时 API、worker/helper、维护调用和 Redis 均停止；mock 服务仍存活但不写应用/队列状态。在这一个停写窗口对 11 份非空 SQLite、游标、原合成主密钥、完整 AOF 目录、目录/manifest 和配置指纹备份。SQLite 使用 backup API，不复制在线主库冒充快照。
6. 快照后在原合成源目录新增收藏 B，确认源中有 B。新目录恢复后逐库完整性/外键/表计数与快照时一致，B 不存在；恢复没有修改原源目录或快照。
7. 启动新的专用 Redis，消费前精确比对两条 stream、consumer group、PEL 消息/消费者/投递次数以及永久身份、queued/已归档 done 状态。重领 PEL 后 queued 收口为 completed，重复同一投递不再次执行 Agent，旧 journal owner 写入被拒绝。队列的 done 不当作订单/支付成功。
8. 验证恢复模型 registry 能解密原合成凭据；错误与缺失主密钥都不能成功。缺 key 的应用初始化会在专用负向测试目录生成新 key，然后因历史密文无法解密而失败；该行为没有被包装成成功，快照工具本身另有前置 key 检查。
9. 从快照冻结的 5,700 件目录，使用同一 mock embedding 配置，在不存在旧存储的新目录重建嵌入式 Qdrant；核验全部点、维度、模型/目录身份、零缺失/旧/坏点。API 随后冷启动，订单 prepare/resolve 幂等重放，21 条 SSE 全量及 Last-Event-ID 后缀精确一致，候选/比较 revision、来源核验与跨买家拒绝保持。过期确认仍返回 409，取消只回补一次库存。回放不新增 chat 请求。
10. 所有自己创建的 API、mock、Redis 进程退出。临时数据库、AOF、快照、密钥与负向测试目录一并清理；证据只留聚合、指纹和合成服务日志，没有 token/主密钥/模型密文正文。

## 复现与启用

在已安装项目冻结依赖和 Redis 的干净工作树、Python 3.11 环境执行：

```bash
python -m scripts.ops.mock_recovery \
  --redis-server /实际安装路径/redis-server \
  --output eval/verification/新的隔离恢复目录 \
  --require-source-stable
```

本云端实际解释器为 `.venv/bin/python`，Redis 路径为 `/tmp/voyacart-redis/src/redis-server`；这些是环境记录，不是用户机器安装要求。驱动不安装软件、不启动 Docker、不读取被阻止的浏览器路径，不修改真实 `.env`。输出目录必须不存在，旧失败不会覆盖。

这是宿主侧开发/验收工具，依赖 `scripts.ci.*` 与 Redis 可执行文件；不承诺 Docker 镜像包含完整演练依赖。镜像里的普通状态 backup/verify/restore 使用独立 `scripts.ops.state_snapshot` 接口，不能将本演练命令当作容器健康检查。

## 结论与仍未验证

实际完成的是同一停写窗口内的**合成恢复组演练**：应用 HTTP 状态、多库、真实 Redis AOF 队列状态、原密钥连续性和冻结目录重建共同恢复，并有业务重放验证；没有仅把三个互不相关组件测试拼成端到端结论。

不过，队列 Agent 为可控合成实现，正式 API 的 HTTP 交易/候选链路与队列 helper 分阶段运行；未启动正式 API+worker+Qdrant server 的并发容器拓扑。索引是客户端嵌入式 Qdrant，服务端 snapshot/部署未验证。测试不证明在线跨库原子备份、生产 RPO=0、生产 RTO、真实模型质量、容器升级/回退、旧 schema 回滚、TLS、公网入口或真实浏览器体验。

B 的缺失是停写快照恢复的预期边界：只承诺已纳入该快照的提交可恢复，不承诺快照后的写入可凭空出现。代码与配置保持同版本，因此属于 rollback-to-snapshot；不等于任意旧版本代码可读取新 schema。演练未触碰用户运行状态，回退仅需撤回新增 driver/测试文件；不用迁移或删除实际数据卷。
