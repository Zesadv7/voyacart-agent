# M5：队列身份保留与服务端期限

日期：2026-10-16（Asia/Shanghai）。实施基线：`6b4128960a520a25f5a5e8ed56c0b00675a3e5fd`（冻结 M4）。本记录只涵盖 Redis 队列切片；整轮运行期限、AGUI journal 补终态、HTTP 故障关闭及共享熔断由同期 M5 独立切片集成。

## 需求与范围

- 排队/运行中的身份不能因一小时 TTL 消失；原始 payload 与幂等指纹必须可查。
- 未显式传 `max_pending` 的旧入口也必须有原子背压，保留双流 pending + lag 合计准入。
- 排队资格必须有服务器期限，覆盖已经领取、但仍等同会话租约的任务；过期不能开始 handler。
- 维护只能有界处理，不扫描永久墓碑；AGUI 过期需要持久重放给 API，直到 journal 已确认。
- 保留 Redis Streams、租约、心跳、ACK、死信、归档与 at-least-once 语义，没有重写队列或宣称 exactly-once。

## 实现

关键源码：

- `app/infrastructure/queue/redis_stream_queue.py`
- `app/infrastructure/queue/maintenance.py`
- `tests/test_queue_deadlines.py`，以及 `tests/test_phase4_queue.py` 的旧命令替身适配

具体变化：

1. 构造器新增 keyword-only `max_pending=200`、`max_age_seconds=900`。`enqueue` 的逐次上限只可收紧构造上限；零、负数、布尔值及非有限期限拒绝。默认值是有界起点，不是测得的生产容量承诺。
2. Lua 使用 Redis `TIME` 写 `accepted_at` 和 `queue_deadline_at`，不信任 task 的客户端 `enqueued_at`。非终态不再设置 EX；所有新任务（legacy/AGUI）均保留完整 task 和 fingerprint。
3. `voyacart:queue:deadlines` 只索引尚待启动/重试的任务；进入 running、done 或 failed 时原子移除。`expire_due(limit=100)` 每次最多处理 limit 个到期身份，并最多返回 limit 个待 journal 化的 AGUI task；允许范围为 1–1000。
4. 过期原子写永久 `failed`，固定错误码 `QUEUE_DEADLINE_EXCEEDED`；保留 task、fingerprint 和终态时间。legacy 无需 journal。AGUI 写独立 `voyacart:queue:expired`，读取后轮转而不删除，API 调用 `acknowledge_expired(task_id)` 后才移除，因此响应丢失/调用方崩溃可以再次补终态。
5. worker 在等会话租约的循环、running CAS、真正调用 handler 前检查资格。过期维护先赢时仅 ACK，不运行 handler；running 先赢则排队维护不能终止已开始运行。身份在最后检查前丢失时失败关闭，保留 pending，不重建或执行。
6. 已 running 的重投也不能无限占住 consumer 等会话：单次领取等待受到 `max_age_seconds` 限制，超时释放本 owner 租约并留 pending，不能以排队错误覆盖既有 journal 运行。Redis 请求/调度延迟是检查的附加窗口，不宣称硬实时上限。
7. 仍有旧状态、但没有服务器期限的已领取消息，以 Redis Stream ID 的服务器时间检查，并在实际访问时去除旧 TTL。已丢失身份不会从当前请求猜指纹；无 worker 的历史未迁移键仍需受控 PERSIST/backfill，不在本次自动全量迁移。
8. 等 journal 确认的过期项禁止提前压缩成墓碑；归档后 `get_task` 从完整归档恢复，归档缺失显式报错。晚到死信不能覆盖已经 failed 的不可变终态。
9. `depth()` 仅把不存在的流视为空；连接失败、wrongtype 等向上抛出，不再假报健康 0。尚未建消费组的流按 XLEN 计，Redis 无法计算 lag 时保守计数。准入仍由 Lua 完成，不依赖 depth 预检。
10. 记录低基数 `expired`、`failed`、`replayed`、`rejected_full` 事件；expired 在新终态转换时计一次，重复 materialization 查询不重复计数。白名单在主 M5 集成切片维护。

## 启用与回滚

- 配置接线、API recovery 周期和 journal 终态落盘由主 M5 切片统一启用；只部署本队列文件不等价于 AGUI 已经拥有完整补终态链路。
- deadline ZSET 对新任务生效；升级前仍带 TTL 的存量须先 dry-run 统计并按自有 key 受控 PERSIST/backfill。没有执行生产迁移，也无法自动恢复已失去的幂等身份。
- 终态/墓碑仍永久保留，完整 payload 在安全归档之前保留。默认准入限制在途数，不代表永久历史成本或内存总量常数。
- 回滚前停写、排空或明确中断在途，保留 Redis AOF、SQLite 及归档。旧代码会重新引入非终态一小时 TTL，不能只改回代码便宣称身份保留不受影响；不能靠删除 Redis/SQLite 数据回退。
- 本切片没有生产容量、容器部署、真实模型质量或端到端 RTO 验收结论。主 M5 仍须完成联合后端回归、故障/负载证据和文档索引整合。
