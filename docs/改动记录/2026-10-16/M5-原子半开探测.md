# M5：原子半开探测与旧调用隔离

日期：2026-10-16（Asia/Shanghai）。实现基线：`6b4128960a520a25f5a5e8ed56c0b00675a3e5fd`。本条是 M5 的共享工具熔断切片，不替代 M5 全链路与容量验收。

## 需求与原行为

共享注册表原来用 Redis JSON 读改写累计失败；冷却结束后，每个调用都可把 `half_open` 写成 1 并获准执行，成功结果则直接删键。需要原子失败计数、一个有到期时间的探针 owner，以及拒绝旧调用结果的代次 fence。

修改前在冻结工作树、隔离真实 Redis 7.4.2 上执行同一合同驱动：

- 32 个并发半开申请全部获准，合同要求只有 1 个，失败。
- 用读屏障确定性安排 32 次并发失败读取同一旧值，最终失败数只有 1，合同要求 32，失败。
- [冻结驱动](../../../eval/verification/2026-10-16-m5-breaker/baseline/regression_driver.py)、[原始失败日志](../../../eval/verification/2026-10-16-m5-breaker/baseline/pytest.log)、[基线指纹](../../../eval/verification/2026-10-16-m5-breaker/baseline/manifest.json)。这些是故障合同，不是容量/吞吐测量。

## 实现

- `app/infrastructure/shared_breaker.py`：一个 Redis Lua 状态机处理 acquire、success、failure、status。失败累计、打开、单探针认领以及结果校验均在 Redis 原子执行；生产路径使用 Redis TIME，测试可显式注入时间。
- 每次打开、认领探针、探针成功关闭都换随机 `epoch`，避免 TTL 删除后重新建键发生 ABA；探针结果必须同时匹配 epoch、owner 且未过 deadline。闭合阶段的在途调用也绑定 epoch，不能在较新熔断周期清零或增加失败。
- `app/infrastructure/resilience.py`：为每次工具调用保存显式 permit，结果直接传回同一 permit。超时收集用子任务、嵌套同名工具、并发协程均不会覆盖外层凭据。
- 中间件探针租期为该工具执行超时加 1 秒；独立注册表默认探针租期 60 秒。Redis 状态 TTL 至少覆盖两倍探针租期与十倍冷却期，且至少 60 秒。取消或进程退出不无条件释放他人的探针，有限租期到期后只有一个新 owner 可接手。
- 保留 `allow_async` 布尔兼容入口：同一个 asyncio Task 中顺序的 allow/record 由弱引用任务表传递 permit。嵌套或跨任务传递结果应使用显式 acquire/permit。无 permit 的兼容记账仅可作用于 closed 状态，不能清理打开状态或抢占探针。
- 本地 `CircuitBreakerRegistry` 实现未变；没有配置 Redis 时仍使用本地实现。Redis 已配置但故障时明确保留 fail-open，旁路调用不携带共享 epoch，Redis 恢复后也不提交旧旁路结果。

## 启用、升级与回滚

- 沿用已有 `BREAKER_SHARED` 装配开关，不修改默认策略、`.env` 或生产数据。JSON key 命名不变，旧 JSON 在原子访问时被识别；无需全库迁移或清键。
- 要获得新保证，应协调全部相关 API/worker 升级或重启。旧进程仍可无条件删键/读改写，滚动混跑期间不能保证单探针或 fence。
- 回滚为恢复旧版本并协调重启；旧版本能够读取基础 JSON 字段，但会失去本条原子性与旧回调隔离保证。不为回滚删除共享 Redis 数据。

## 边界与未完成

- 单探针指 Redis 可用时最多一个有效 owner；租约到期不等于强制停止已经发给远端的操作。若下游忽略取消，旧调用仍可能在远端继续执行，但其迟到结果不能修改新熔断状态。
- Redis 断连期间继续放行，不能宣称跨实例严格单探针；`status_async` 此时返回兼容的 closed，不是健康证明。上层运行准入另行约束。
- 这里只验证真实 Redis 与确定性工具合同，未验证生产故障率、吞吐收益、外部模型链路或容器部署。
