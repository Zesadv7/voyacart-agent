# M4：持久候选、按规格比较与目录核验前端

日期：2026-10-16（Asia/Shanghai）；前序代码基线 `1871718`。本记录只覆盖 M4 前端，不替代后端持久化、真实 HTTP、安全评测或真实浏览器结论。当天索引由 M4 集成任务统一维护。

## 需求与实施

把 App 原先会被新搜索和会话切换清空的内存比较替换成服务端会话候选工作区。按商品＋SKU保留最多30项，比较使用候选ID有序列表（最多3项）。新搜索仍替换当次结果，候选与比较独立读取恢复。

- 新 `frontend/src/lib/candidateWorkspace.ts` 严格解析工作区/核验响应，校验buyer、session、schema、revision、候选/比较外键、SKU和金额；只有身份绑定且available的当前SKU进入后续表单。响应不能把未知历史来源提升成可信商品。
- `frontend/src/hooks/useCandidateWorkspace.ts` 每次会话/身份/连接变更独立实例与代次。GET与写回包按最高revision合并；A→B→A、旧重放和卸载不复活候选。15秒有界等待；已有候选读取失败不清空。
- 每动作固定request_id和expected_revision；网络结果不明保留同键，sessionStorage只存动作ID/来源引用/版本，不存报价或地址。409先重取、保持待操作意图，只有用户明确核对后新键重试；最新读取失败时禁止换键。存储异常持续提示恢复限制。
- App当前/历史商品可保留明确SKU，详情显式选规格可保留同商品不同SKU。来源是实际SDK run或历史batch.runId，不能猜最后消息/工具。收藏仍独立保存；收藏详情走重新查询，不冒充可信run导入。工具结果小卡保持只读。
- 新 `components/CandidateWorkspace.tsx` 与局部CSS显示保存时间、来源、历史价格/库存、身份状态、比较/移除、持续错误/重试与目录核验。旧库存0不阻止核验；当前缺货/身份不符/条款改变保留历史、禁止从候选准备。
- `ProductComparison` 用candidate_id为key，展示同商品双SKU、保存时间及历史单价/库存，不横比不同币种最低价。
- 核验结果与保存快照分离，目的地/币种改变或会话切换使暂态失效。仅成功当前卡进入既有OrderIntentForm/M2 prepare/resolve；不自动批准。表单保留核验地区，最终确认仍只含商品金额、未支付、未安排发货。
- `commerceClient.ts` 新 productsRunId 绑定SDK/恢复run，持久旧缓存无显式来源时保持未知；workspaceRequest保留status并透传结构化code/current_revision/detail。
