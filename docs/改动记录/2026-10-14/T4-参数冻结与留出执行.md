# T4 参数冻结与一次留出执行

需求：在开发集全部策略完成后，按全库 nDCG@10 选定默认策略、冻结参数，再执行一次留出和中文派生评测。

`scripts/eval/run_esci.py` 新增 `--freeze-from` 和显式 `--profile holdout --frozen`。冻结读取完整开发报告，要求六个策略都有明确状态；未配置精排的两个策略记为未执行，其余须完成。按开发全库 nDCG@10 最大值选策，相同分数按已记录的策略顺序选择。清单记录源码与开发输入核验、目录、检索参数、嵌入和精排的模型及网关内容指纹；嵌入批量上限、客户端超时、精排协议及超时同时记录。

留出档重新核对开发证据、目录和有效服务配置，使用清单选定策略。读取留出标注前以独占创建记录 `eval/esci/baselines/holdout-attempt-v1.json`；成功或失败均保留首次尝试，后续命令在读取留出标注前停止。已存在 `approved-v1.json` 时同样停止，保持已保存的基线。成功后写入 `approved-v1.json`，包含四组指标、原始报告位置及内容指纹。开发档继续独立执行，保留留出和中文派生集未执行状态。

[20 项最终检查](../../../eval/verification/2026-10-14-t4-freeze-completion-contract/pytest.log)通过，使用独立构造目录和本地假嵌入／索引，模型与外部 HTTP 调用 0。检查覆盖原排序和约束合同、全策略选策、精排未配置、配置变化时拒绝进入留出、成功和失败均只允许一次尝试、四组结果及批准记录；精排协议／超时变化与仅有已保存基线的场景也在读取前拒绝。夹具、开发报告、冻结清单和一次尝试记录存于同一证据目录的 `fixtures/`，读取守卫保持首次运行输入字节；各准备阶段日志原样保留。

只读审查发现精排协议和超时尚未进入初版清单，直接补齐实际生效字段后，真实获胜精排策略的两项回归通过。初版夹具在检查重复尝试时改写输入文件，随后使用读取守卫，在新目录保留原始夹具字节；各阶段证据保持原样。
