# C1 推送路径优化

## 需求与版本

用户要求将重点转到后端和前端界面，先采用针对性检查推进功能。数据准备继续后台收尾。改造前版本为 `7f29c08`，工作分支为 `feat/C1-sse-delivery`，本地实现已完成，PR 待统一安排。

## 实现

- `AGUIJournal.run/events` 使用 SQLite 只读连接和读取事务，保持同一快照内的游标、状态及事件一致；读路径释放写锁竞争。
- `AGUIRuntime` 启动时恢复过期运行，之后每 5 秒执行一次；关闭时停止恢复任务，原有显式停止与中断收口继续保留。
- `AGUI_DELTA_COALESCE_MS` 默认 0；设置 50 时合并窗口内同一消息或工具调用的连续增量，文本内容和事件边界保持一致。
- 每个运行共享进程内信号，写入成功后通过已有 Redis 背板广播。API 沿用现有单一背板订阅；断开后重新订阅。SSE 同时保留 150ms 日志轮询，覆盖无 Redis 或信号丢失；空闲心跳间隔为 15 秒。
- 装配位置同步传入背板和合并配置；SQLite 默认、Redis 可选、旧入口与既有运行取消机制保持可用。

## 验证

- 改造前 AG-UI 相关测试：82 项通过。[日志](../../../eval/verification/2026-10-14-c1-baseline/pytest.log)。
- 改造后首轮针对性测试：89 项通过，覆盖读写并发、周期恢复、文本与工具参数完整性、丢信号、Redis 故障及游标重连。[日志](../../../eval/verification/2026-10-14-c1-delivery/pytest.log)。
- 后续增加真实 Redis 发布订阅检查，并执行完整后端测试：1948 项通过，1 项共享配额时序测试失败。失败涉及已有 `test_quota_wait_is_bounded_and_configuration_conflict_is_closed`；该项单独重跑通过，0.56 秒。两次结果分别保留：[完整运行](../../../eval/verification/2026-10-14-c1-integration-rerun/pytest.log)、[单项复核](../../../eval/verification/2026-10-14-c1-integration-rerun/throttle-recheck.log)。
- 首次完整测试命令误带另一工作目录中的 T1 测试路径，退出码 4；已修正命令并保留[原始输出](../../../eval/verification/2026-10-14-c1-integration/pytest.log)。
- 锁竞争检查：同一数据库的另一个连接持有写事务时，旧读路径等待释放，耗时约 399ms；新读路径在写锁仍持有时返回，耗时约 0.56ms。这是单次路径检查，完整负载容量与 P95 仍待测量。[基线](../../../eval/verification/2026-10-14-c1-baseline/read-lock.json)、[改造后结果](../../../eval/verification/2026-10-14-c1-delivery/read-lock.json)、[源码指纹](../../../eval/verification/2026-10-14-c1-delivery/manifest.json)。

## 启用与后续

默认 `AGUI_DELTA_COALESCE_MS=0`；需要合并时设为 50，恢复为 0 即关闭合并。配置 Redis 后自动使用背板信号，读取轮询持续提供兜底。完整模型回归、容量矩阵和跨进程故障演练留待后续统一验证，当前记录只声明上述实际结果。
