# R2 模型状态码分类修复

## 需求与根因

实际故障演练中，主模型返回 HTTP 503，异常消息为 `Error code: 503 - {'detail': '注入的模型故障'}`。共享瞬时故障判据只识别消息关键词，该响应直接抛出，未进入已有重试和备用模型回退。

原始失败保留在 [模型演练日志](../../../eval/verification/2026-10-14-r2-model/command-010.stdout.log)，HTTP 503 响应见第 6576 行，最终异常见第 6786 行。

## 实现

- [transient.py](../../../app/infrastructure/transient.py) 优先使用异常的结构化 `status_code`：408、429 和 500–599 进入现有瞬时故障流程，其他明确 HTTP 状态快速失败。
- 408 按现有请求超时语义补齐；5xx 按已有服务故障规则补齐。无状态码时保留原消息判据，包括 SSE 流内 `Throttling.Concurrency`。
- 共享函数继续供模型重试、编排层和响应恢复引用，重试次数、退避和备用模型调用沿用原实现。
- [分类测试](../../../tests/test_phase3.py) 覆盖中性异常消息与 HTTP 状态优先级。[运行时测试](../../../tests/test_model_runtime_counting.py) 使用真实 OpenAI SDK 和 `httpx.MockTransport`，覆盖重试成功、重试耗尽后回退、备用凭据和窗口、逐次调用计量，以及主备模型配额释放。
