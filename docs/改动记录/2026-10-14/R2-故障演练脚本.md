# R2 故障演练脚本准备

## 需求与改动

按 PLAN.md R2 和 DESIGN.md 5.5 准备六项演练。本记录保留脚本准备阶段：当时容量矩阵尚在运行，仅验证脚本协议。后续六项实际演练结果见 [实际故障演练记录](R2-真实故障演练.md)。

- `scripts/loadtest/faults.py`：每次指定一项演练，创建全新 `voyacart-r2-*` Docker 项目，使用独立数据卷、端口、运行镜像和前端镜像。项目或数据卷已存在时直接报错。
- 服务与凭据固定为项目内的假模型、独立假嵌入、Redis、Qdrant和演示数据库。真实环境变量与本机 `.env` 不进入演练配置。
- worker 演练在首段文本产生后发送 KILL，核对租约加 5 秒恢复、重新投递后模型请求计数不变及仅一次 RUN_STARTED；API 演练定位当前 SSE 的实际上游，停止该副本，经 Nginx 使用 GET 和 Last-Event-ID 续传。
- Redis 演练核对进程内降级事件、运行错误、停机期间零新增模型请求和重启后正常入队；嵌入演练只停止独立嵌入服务，本地向量开启，核对返回商品及 `local_embedding`。
- 主模型演练注入确定的 429 和 503，核对重试、备用模型、回退事件及恢复；库存演练复用 `hotspot.py`，500 次批准抢库存 100，核对数据库库存归零、无负数和批准前订单数为零。
- `mock_llm.py` 新增 `MOCK_FAULT_CONTROL=1` 才能访问的控制端点：按模型注入有限次或持续故障；审计只保存模型和状态计数。默认关闭。
- 每项生成新证据目录，保存源码内容指纹、原始 SSE 字节、每条命令与原始输出、运行快照、失败样本和容器日志。结束停止本项项目，保留其卷供核查。

## 执行方式

从整合后的代码构建镜像，实际源码指纹会写入当次 `source.json`。每项使用新项目名和新证据目录，例如：

```bash
.venv/bin/python scripts/loadtest/faults.py worker \
  --project voyacart-r2-worker-20261014 \
  --port 8086 \
  --output eval/verification/2026-10-14-r2-worker
```

将 `worker` 分别替换为 `api`、`redis`、`embedding`、`model`、`hotspot`，同时替换项目名和输出目录。每项停止后端口可复用。嵌入演练另加 `--model-cache <已经准备好的 fastembed 缓存根目录>`；脚本复制本机模型缓存，运行时采用本地文件模式。

`eval/verification` 被 Docker 构建上下文排除，因此带上游标识的临时 Nginx 配置由脚本生成在 `.cache/r2/`，同一份配置也归档到证据目录；生产 Nginx 配置保留原内容。
