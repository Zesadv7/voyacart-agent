## 保留的失败与修复

- 首轮 worker 恢复检查将客户端观测时间与服务端租约相减，得到负时间差并失败。改为用运行快照的服务端更新时间比较，服务恢复逻辑保持原样。[首次失败](../../../eval/verification/2026-10-14-r2-worker/failure.json)保留，复测记录服务器时间。
- 首轮 429 正常回退，503 直接以 AGENT_ERROR 结束。共享故障分类补齐结构化 HTTP 状态码，408／429／5xx 进入现有重试与回退；其他明确状态快速失败，SSE 文案判据保留。[114 项回归与原始失败](../../../eval/verification/2026-10-14-r2-model-status/README.md)和[改动记录](R2-模型状态码.md)说明根因。
- 首轮热点准备请求被系统代理接管，应用与 Nginx 没有收到确认请求；旧脚本在解析 JSON 前未保存响应，因此具体 HTTP 状态与正文未知。客户端使用 `trust_env=False` 直连，解析前记录每次响应状态和原始正文；清理在途准备任务后关闭日志。[真实本机 HTTP 回归](../../../eval/verification/2026-10-14-r2-hotspot-client/pytest.log)证明错误代理下仍直连，503 非 JSON 正文完整保留。[首次失败](../../../eval/verification/2026-10-14-r2-hotspot/failure.json)保留。

所有无批准的选购演练都核对订单数为 0。模型轨迹中检索工具成功，现有工具熔断保持关闭；该轨迹证明重试、备用回退和恢复，工具熔断触发仍未覆盖。容量实验、完整真实模型 Harness、干净机器部署以及数据／质量验收继续单独处理，六项演练通过不替代这些结果。

启用故障控制需要 `MOCK_FAULT_CONTROL=1`，默认关闭。测试客户端只改变压测直连和证据记录。生产状态码分类直接补齐既有规则，沿用原重试、配额、预算和租约。各次命令、原始输出、SSE、报告与源码内容指纹保留在链接目录。
