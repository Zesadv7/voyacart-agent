# T3 准备：显式商品目录与旧基线复核

## 需求与根因

PLAN 的 T3 要求旧评测显式选择各自的商品目录。整合检查将 v1 金标和批准基线用于当前默认的 v3 目录：500 件历史商品的金标对应了 3,700 件候选，新增商品改变了 Precision 与空结果判定。原门禁为 BLOCK，原始失败保留在 [integrated-v1-recall](../../../eval/verification/2026-10-14-integrated-v1-recall/run.log)。

本轮完成目录选择前置修复，默认目录继续使用现有 v3；真实 ESCI 默认切换与提示词调整由后续 T3 整合处理。

## 具体变更

- [seed_products.py](../../../app/infrastructure/persistence/seed_products.py) 的 `build_seed_products(path=None)` 支持显式路径和 gzip，文件逐行解析 JSONL。标题中的 U+2028、U+2029 和 U+0085 保留为字段内容。省略路径时沿用当前镜像目录／开发目录选择。
- [run_product_recall.py](../../../scripts/eval/run_product_recall.py) 新增 `--catalog-file`，将读取的商品直接注入 `build_usecase`。指定文件加入输入内容指纹清单，参与运行结束时的稳定性核对。
- 默认 3,700 件目录及旧目录文件保留；原批准基线和所有门禁阈值沿用原值。
- 两个现有测试文件补充真实 JSONL、gzip、Unicode 和 CLI 目录选择合同。
