## 失败与处理

1. Homebrew 在安装 Node.js 22 的证书依赖时出现内部错误。已改用项目本地的官方二进制包。保留[错误摘录](../../../eval/verification/2026-10-14-environment-prepare-141356/brew-node22-error.log)和[官方包校验记录](../../../eval/verification/2026-10-14-environment-prepare-141356/node-install.json)。失败的 Homebrew 操作已安装 libuv 1.53.0，完整下载进度未保存。
2. 前端锁文件的 304 个下载地址指向内部 npm 镜像，连接反复重置。使用 npm 的 `--replace-registry-host=always` 从公开仓库获取相同锁定版本，并保留完整性校验。原锁文件保持逐字节一致。保留[首次安装日志](../../../eval/verification/2026-10-14-environment-prepare-141356/npm-ci-first-debug.log)与[成功安装日志](../../../eval/verification/2026-10-14-environment-prepare-141356/npm-ci-public-registry.log)。
3. 供应商 1 的模型列表包含当前聊天模型，嵌入模型列表为空；调用 `text-embedding-v4` 返回 HTTP 404、`model_not_found`。后续远端向量索引与评测等待独立的 `EMBEDDING_BASE_URL`、`EMBEDDING_API_KEY`、`EMBEDDING_MODEL` 配置。保留[模型列表检查](../../../eval/verification/2026-10-14-environment-prepare-141356/provider-models.json)与[嵌入请求结果](../../../eval/verification/2026-10-14-environment-prepare-141356/remote-embedding.json)。
4. npm 审计返回 6 项现有依赖漏洞：2 项中等、2 项高危、2 项严重。原依赖版本保持基线状态，升级需另定范围。保留[完整审计结果](../../../eval/verification/2026-10-14-environment-prepare-141356/npm-audit.json)。

## 使用与停止

本机前端命令使用项目内 Node.js 22：

```bash
export PATH="$PWD/.cache/node-v22.23.3-darwin-arm64/bin:$PATH"
npm --prefix frontend ci --registry=https://registry.npmjs.org --replace-registry-host=always
npm --prefix frontend test
npm --prefix frontend run build
```

基础服务使用已有 Compose 文件和本机 `.cache/compose.local.yaml` 端口覆盖文件：

```bash
docker compose -p voyacart-agent --env-file .env -f docker/docker-compose.yaml -f .cache/compose.local.yaml up -d redis qdrant
docker compose -p voyacart-agent --env-file .env -f docker/docker-compose.yaml -f .cache/compose.local.yaml stop redis qdrant
```

端口覆盖文件将 Redis 绑定到 `127.0.0.1:16379:6379`，Qdrant 绑定到 `127.0.0.1:6333:6333`。服务数据保存在项目独立命名卷中。Node.js、本地模型缓存和依赖安装目录均属于本机产物。
