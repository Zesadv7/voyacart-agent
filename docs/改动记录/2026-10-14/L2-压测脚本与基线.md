# L2 AG-UI 压测脚本与历史基线

2026-10-14。用户将后端与前端置于数据及完整压测之前，因此 C1–C3 已先行实现。本阶段从原始提交 `7f29c08` 导出未经并发改造的后端，补测独立历史基线；原提交源码指纹与部署方式随证据保存。

## 实现

- `scripts/loadtest/locustfile.py` 每轮新会话，思考间隔 5–15 秒；默认 10% 用户在首文本后主动断开，用原游标 GET 续传。
- `client.py` 完整消费 SSE，忽略心跳注释，逐条核对运行 ID、事件序号连续且唯一；记录首事件、首文本、完成时间、HTTP／运行／传输错误。每轮原始数据写入 CSV。
- `analyze.py` 生成三组 P50／P95／P99、成功吞吐、错误率、错误码与续传数。分位数采用 nearest-rank，缺失首 token 的失败仍计入错误率。
- `hotspot.py` 为同一 SKU 准备 500 张确认单，完成后并发批准，保存全部响应、CSV 和汇总；准备阶段的订单数必须为 0。
- Locust 及其依赖使用独立环境，项目运行依赖保持原样。旧的 `scripts/locustfile.py`、`scripts/loadtest.py` 保留。

- 协议和统计测试 8 项通过，见 [日志](../../../eval/verification/2026-10-14-l2-script-fixed/pytest.log)。覆盖断线游标、重复／缺失序号、缺终态、运行错误、网络错误、SSE 多行与不完整帧、带失败和缺失值的分位数。

- 真实双 API／双 worker 预检查 3 轮，强制 100% 断线续传，全部成功，序号连续。见 [原始报告](../../../eval/verification/2026-10-14-l2-script-runtime/actual/report.json)。该检查使用快速假模型，只验协议。

## 历史基线环境

原后端提交 `7f29c08`、单 API 进程、进程内执行、独立 SQLite、无 Redis。模型使用专用假服务，首 token 0.8 秒、间隔 0.03 秒、300 个模拟 token、10% 确认轨迹。应用保留默认模型并发 2、最小间隔 1 秒。知识与商品向量复用相同冻结旧目录的 Qdrant 集合，聊天模型与数据库独立。

机器为 Apple M4、10 核、16 GiB 内存；Docker 分配 4 CPU、约 7.74 GiB。自动化调度关闭，Colima ARM 使用已有加密库兼容参数。前端预览服务保持运行，属于本机实验环境；资源采样与完整配置在 [证据目录](../../../eval/verification/2026-10-14-loadtest-baseline/)。这些条件随报告保留。

热点库存实测：500 张确认单全部准备成功，批准前订单 0；并发批准成功 100、库存不足 400，最终订单 100、库存 0。批准阶段耗时 6.693 秒。权威库存前后值、每张单据与原始 CSV 均在证据目录。

1／2／4／8 用户四档全部执行，合计 27 次运行全部成功；2 次随机抽中的重连序号连续。运行日志数据库同为 27 次 completed，所有在途请求已结束。成功吞吐依次为 0.054／0.091／0.148／0.156 次每秒。4→8 用户吞吐只增加 4.98%，完成时间 P95 从 26.873 秒增至 53.854 秒，观察到 4–8 用户附近的平台。

每档的首事件／首 token／完成时间 P50／P95／P99、CPU 与内存采样、错误和原始 CSV 见 [完整报告](../../../eval/verification/2026-10-14-loadtest-baseline/REPORT.md)。本次属于短程默认限额基线，小样本 P99 等于最大值。写锁重试计数尚未专门埋点，明确记为未知；后续 R1 关闭网关配额的容量矩阵需要同口径历史对照，不能混用吞吐结论。

最终相关测试 21 项通过，默认项目环境可收集 1,990 项测试，验证新脚本未让普通测试依赖 Locust。见 [最终检查](../../../eval/verification/2026-10-14-l2-final-check/)。本卡没有修改业务代码，全量业务测试沿用前次整合结果。
