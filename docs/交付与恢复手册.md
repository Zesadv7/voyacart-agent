# 当前版本：本机演示、升级与恢复

目标是单机、私有、无支付的选购 Agent 演示。当前实现与各项结果见 [M6 验收清单](../eval/verification/2026-10-16-m6-integration/README.md)。真实 Docker 构建/启动、TLS 公网入口、真实浏览器录像、真实模型门禁仍未完成；配置解析、mock 和 JSDOM 不替代这些门禁。

## 1. 陌生人从零开始

需要 Python 3.11–3.13、uv 0.12.23、Node.js 22；队列及全部后端回归还需要官方 Redis。使用干净 checkout，工作目录不放真实 `.env` 或运行数据库。不要把个人密钥复制到测试目录。

```bash
uv sync --frozen --extra esci --extra optimization
npm --prefix frontend ci
# 自动生成临时数据、启动回环 mock 和 API、检查候选/交易/SSE 后退出。
uv run --no-sync python -m scripts.ci.mock_smoke --signed --output eval/verification/local-first-http
npm --prefix frontend test
npm --prefix frontend run build
```

报告目录必须新建，不能覆盖旧失败。此自动路线不需要真实模型密钥，运行期间只访问回环假模型；不是持续运行的网页预览。`mock_recovery` 另外检查一致快照恢复，见下文。

## 2. 五分钟演示脚本

成功路线：

1. 新选购输入“查找寄到中国的旅行背包”，查看当前搜索结果、源站点/原文/推断和演示字段说明。
2. 主动保存两个商品/SKU 到候选，加入比较。改查询或零命中不会清空候选；同商品不同 SKU 可分开保存。
3. 从候选重新核验当前目录，确认历史候选不是锁价或库存预留。当前核验不调用模型，但后续 prepare/resolve 仍再次核验。
4. 填写明确的合成收货信息，生成确认单，核对商品金额、数量、目的地、有效期。点击批准后才创建未支付订单意向。
5. 刷新并恢复会话/候选/比较/意向；重复批准仍同一单，库存只扣一次。取消需再次明确批准，回补一次。

失败恢复路线：两标签对同一候选 revision 修改时旧写入返回409；刷新取新集合，候选不凭空丢失。过期/缺货/退市核验失败保留历史信息，禁止用旧批准执行新报价。SSE 断线从已保存 cursor 重放；worker 崩溃可能收口 interrupted，并不承诺恢复模型内部生成。

真实浏览器动作仍须外部环境验证；现有接口/组件/SDK 证据不能冒充录像。本轮没有声称真实支付、发货、商家库存或运税最终结算。

## 3. 单机 Compose 路线

新增 [GitHub hosted 容器 Mock CI](容器Mock-CI.md)：独立内部网络、签名 HTTP、实际容器重启/重建、命名卷与同镜像快照回退。以下原交付限制保留其历史含义；当前容器是否通过以具体提交的 Actions 报告为准。

普通 Compose 默认只有回环 API 与前端端口；Redis/Qdrant 不发布宿主端口。scale 默认只有回环 nginx 入口。两个形态都共享同一 DATA_DIR 卷，多进程必须用 Qdrant 服务端。依赖及安全配置见 [M6 配置护栏](改动记录/2026-10-16/M6-部署配置护栏.md)。

```bash
# 配置校验；这里全部是 mock 占位值。
LLM_BASE_URL=http://mock-llm:8081/v1 LLM_API_KEY=local-mock-only \
  docker compose -f docker/docker-compose.scale.yaml --profile mock config --quiet

# 真实 Docker 可用时，使用独立项目名，避免覆盖已有演示卷。
LLM_BASE_URL=http://mock-llm:8081/v1 LLM_API_KEY=local-mock-only LLM_MODEL=mock-chat \
EMBEDDING_BASE_URL=http://mock-llm:8081/v1 EMBEDDING_API_KEY=local-mock-only \
EMBEDDING_MODEL=mock-embedding LLM_FALLBACK_MODEL= SEMANTIC_CACHE_ENABLED=0 \
  docker compose -p voyacart-mock-review -f docker/docker-compose.scale.yaml --profile mock \
  up -d --build --scale api=2 --scale worker=2
```

这是待在 Docker 主机验证的命令，不是本轮容器成功证据。停止使用相同 project/config 的 `down`，不加 `-v`。首次索引构建用 mock 不收费；真实 embedding 重建可能收费，需独立预算授权。

`RUN_MAX_ACTIVE` 是每进程上限，多个 API/worker 总量为各进程之和；`RUN_TIMEOUT_SECONDS` 约束运行终态，无法强杀不合作协程；`AGUI_QUEUE_MAX_PENDING` 覆盖两个队列入口/两流准入；`QUEUE_MAX_AGE_SECONDS` 是尚未开始任务的服务端资格期。资源/日志限制仅是演示保护值，尚未基于真实容器调优。

`/health` 表示已配置的主要 DB/Redis/prompt 检查通过，不代表所有状态库、worker、完整索引或外部模型健康。API 已启动也不表示模型可用。Qdrant `service_started` 未提升成经实测的 server readiness，检索可能降级；上线必须另核对索引完整性和实际依赖 readiness。

## 4. 停写快照与恢复组

状态包括交易/会话 DB、journal/候选/automation、queue archive、证据、偏好、技能、表单、收藏、模型 registry、prompt registry。只备份 voyacart.db 不够。Redis 保留未完成队列/PEL/身份/期限；模型 registry 需要原主密钥；目录/embedding 身份必须与代码一致。

关键前提：先关闭入口并停止所有 API、worker、automation、维护写入者。SQLite backup API 保证单库一致，跨多个 SQLite 和 Redis 的一致性依赖统一停写窗口。`--quiesced` 是操作员声明，工具不能证明不存在其他写入者。Redis 停止后再复制完整 multipart AOF 目录；不能在线复制其中一个文件。

工具及准确 CLI 以 `python -m scripts.ops.state_snapshot --help` 为准。具体支持布局、安全限制及合成测试见 [快照工具记录](改动记录/2026-10-16/M6-一致快照工具.md)。恢复只写全新目录，不覆盖原目录。外部 DATABASE_URL、未知状态路径、丢失主密钥必须明确处理，不能静默漏掉；正式密钥/数据库不进入源码、证据或交付附件。状态目录必须与只读目录分开（镜像为 `/app/data` 与 `/app/catalog`）；含公开catalog/其他未知文件的旧混合目录会拒绝，不能静默跳过。模型库没有任何可验证密文时也暂不支持快照，需先明确恢复方案，不能伪造业务记录让校验通过。

派生 Qdrant 索引采用冻结目录+embedding 配置重建；原库留存。恢复报告需核对库存/订单、prepare/resolve 幂等、候选/比较、完整 SSE、模型配置解密与队列终态。模型主密钥丢失不能用新生成密钥替代。

自动隔离演练：

```bash
# 官方 redis-server 在 PATH；不读取 .env/真实配置，只建立临时合成数据。
uv run --no-sync python -m scripts.ops.mock_recovery --output eval/verification/local-first-recovery
```

实际覆盖、各段耗时及限制见 [隔离恢复记录](改动记录/2026-10-16/M6-隔离恢复演练.md)。一个快照之后新增的合成操作不会出现在恢复结果，正是快照回退边界，不能据此声称生产 RPO=0；copy/重建/API ready 耗时不是生产灾备 RTO。

## 5. 升级和回滚，不混跑旧协议

- 冻结新旧源码/镜像、锁文件、目录/embedding/collection、配置（无密钥值）、完整恢复组。真实镜像 digest 必须在目标主机产生，本轮没有可冒充的镜像 digest。
- M5 以前的非终态 Redis 身份有旧 TTL。停写并取得快照后先 dry-run，再明确 apply；[旧队列受控升级](改动记录/2026-10-16/M6-旧队列受控升级.md)说明每流分页、缺身份阻塞和旧终态 TTL 的未覆盖边界。
- 新 shared breaker 需要全部相关 API/worker 协调升级；旧进程仍能覆盖/删除状态，混跑不保证单探针或 fencing。不要清 Redis 键“修复”升级。
- 先在恢复副本运行新版本，核对目录身份、库存、订单、候选和过期确认，再切入口。不能用删除数据卷代替迁移。
- 回滚前先停写并保存新版本状态。恢复旧快照会丢失快照后的变更，不能未经决定就覆盖；旧代码也会失去新 TTL/准入/fencing 保障。真实旧版本 schema 回滚和容器升级未在本轮验证。

旧队列命令（只对明确授权的自有 Redis）：

```bash
# REDIS_URL 由操作员安全注入；不要把带凭据 URI 贴到日志。
python -m scripts.ops.queue_upgrade --output upgrade-dry-01.json
# 如果 status=more_batches，用同阶段前一报告继续。
python -m scripts.ops.queue_upgrade --cursor-file upgrade-dry-01.json --output upgrade-dry-02.json
# apply 从头开始，不能沿用 dry-run 游标。
python -m scripts.ops.queue_upgrade --apply --quiesced --output upgrade-apply-01.json
```

旧身份已消失、指纹冲突、来源歧义、扫描/写入中断都是阻塞。工具先核对完整有界来源清单，任一流超过1000项拒绝迁移；大存量需另行受控迁移方案，不能靠截断数据绕过。blocked报告不能继续下一页掩盖错误。scan_complete 只说明两条流遍历完，不证明历史孤立键或所有状态完整；旧终态 TTL 数量单列。本轮只操作临时合成 Redis，未迁移真实库。

## 6. 看见告警后如何定位

- HTTP 503 + Retry-After：区分 RUN_CAPACITY_EXCEEDED、QUEUE_UNAVAILABLE、QUEUE_ACCEPTANCE_UNKNOWN。未知接收要沿原 run/request 键查询，不能换键盲目重提。
- 队列积压/期限：核对 stream pending/lag、终态索引和 queue deadline；delivery done 只说明投递收口，业务运行读取 journal。
- 模型失败：区分 Redis 共享配额拒绝、工具 fail-open 旁路、模型超时和模型响应错误。不要把 SSE 重放当新模型运行。
- SQLite 写锁：先核对多进程/短事务/磁盘位置，当前没有全站锁等待仪表。历史单路径优化与短窗负载不等于全站收益。
- 关联 request、run、task、operation；指标只用低基数状态，不把 buyer/query/密钥当标签。复现证据见 [M5 故障矩阵](../eval/verification/2026-10-16-m5-candidate-probe-accepted/report.json)。这是本地诊断与故障证据，没有声称生产告警接收系统已部署。

## 7. 外部放行前仍要完成

1. 目标 Docker 主机：实际干净构建、依赖 readiness、资源限额、已发布端口、备份卷恢复、升级/回退和镜像 digest。
2. 明确授权的公网目标：TLS、严格身份、随机服务端密钥、正值请求预算/速率、HTTPS Origin；不将 mock 或管理接口暴露公网。
3. 支持浏览器的环境：成功/失败录像、移动端/键盘、双标签 Web Locks、刷新/历史导航。
4. 明确模型网关和预算：完整 Harness smoke/必要 release、真实 ESCI 十场景。当前缺凭据门禁原样保留。
5. 人工完成200类目/50译文抽检并核对来源许可；目前有效人工审核0，模型推断不升级成商家承诺。

用户/操作员需要决定外部环境、授权范围和预算；这些缺口不妨碍查看已完成代码及离线证据，也不应被写成全部计划已完成。

## 8. 接收本地增量交付包

本轮提供的 Git bundle 以原主干 `264ef633e3cd0b431e06e941e89136379eb46022` 为前提，保留 M1–M6 的本地提交与原始证据；不是全历史克隆，不包含未跟踪运行目录。先核对随包 SHA256 与发布清单，再在已经拥有该基线的仓库执行：

```bash
git bundle verify /接收位置/voyacart-m1-m6.bundle
git fetch /接收位置/voyacart-m1-m6.bundle HEAD:refs/heads/voyacart-delivery
git worktree add ../voyacart-delivery voyacart-delivery
```

使用未占用的新分支/目录名，不加 force，不覆盖现有工作。进入新 worktree 后核对 `git rev-parse HEAD` 与发布清单的完整 SHA，再按本手册安装。bundle不是在线部署，不会替你push；SHA256可验证传输一致性，不构成独立签名认证。公开 `.env.example` 和合成测试夹具属于源码，不包含实际访问凭据；真实 `.env`、数据库、AOF、主密钥和依赖缓存不进入新增交付文件。
