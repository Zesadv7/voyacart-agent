# 安全与身份边界

## 私有演示身份

`IDENTITY_MODE=demo` 是隔离演示的客户端声明身份，不能用作公网认证。`hmac` 复用固定 HS256、用途、issuer/audience、签发和过期时间验证；必须启用持久会话归属。

维护者在受控服务器配置至少32字节的独立随机 `IDENTITY_HMAC_SECRET` 后，可使用已有 `python -m scripts.issue_identity_token --buyer-id <买家ID> --ttl-seconds 3600` 本机签发两个独立测试身份。密钥不在网页输入，不放在 VITE 变量，不提交仓库。本文没有生成或配置任何真实密钥。

网页先读取 `/commerce/identity/config`，hmac 模式要求输入维护者通过受信渠道提供的短期凭证；`/commerce/identity` 验证后返回主体和有效期，没有匿名公开签发接口。token 只存当前标签页 sessionStorage，存储不可用时只留内存。退出或401清除授权并卸载旧买家界面，禁止自动重发写请求。每个请求仍由后端验证签名、声明主体和资源归属；浏览器缓存不构成权限。

原有 token 到期前仍有效；退出是浏览器端退出，没有服务端撤销列表，不等于立即撤销已复制的 token。既有长连接在请求建立时验签；浏览器到期退出。公开部署需要由入口限制连接寿命，不能宣称存在实时撤销系统。

## 公网配置护栏

`PUBLIC_DEPLOYMENT=1` 必须同时配置：hmac、会话归属、输出审核、32字节以上且不明显重复的服务端密钥、明确无路径的 HTTPS CORS Origins、正值 `TOKEN_BUDGET_TOTAL` 与 `HTTP_REQUESTS_PER_MINUTE`。字符种类检查只排除明显弱密钥，不能证明随机熵。

直连 FastAPI 同样有正文上限（默认1MiB）和读取期限（默认30秒），不信任 Content-Length；超限/超时在业务执行之前拒绝。请求速率是每个API进程的滚动一分钟总额，返回429和 Retry-After；不是按买家公平配额，不是集群限流、DDoS防护或后台 run/inflight 准入。模型预算、HTTP准入和队列准入是不同边界。

模型连接管理仍仅允许严格模式下的 `MODEL_ADMIN_BUYERS`；运维指标使用独立 `METRICS_READER_BUYERS`。普通签名买家无管理权限。禁止把 Redis/Qdrant/调试端口直接暴露公网；TLS、代理安全和实际部署验收见后续部署里程碑。

## 公开流、历史和日志

正文必须完整审核后一次公开，安全开始/结束/进度仍流式。原生工具参数在完整JSON后做已知字段投影，结果按工具白名单展示；Thinking 只显示活动状态，不公开原始片段。模型真正执行的数据独立保留，公开投影不能改写 SDK 的工具参数或批准动作。

公开事件在写入 journal 前处理，历史读出和SSE重放再处理，原事件序号/断点游标保留。旧版未审核的正文增量在公开重放中清空；可读最终快照经过审核。旧WebSocket、排队中运行、任务结果、异常partial、确认resume、conversation可读流水也走公开边界。原始内部AgentState不是用户日志；没有把内部状态全部当作公开安全数据。

规则覆盖已知凭据形态、敏感字段和危险URL，工具参数/结果还有字段白名单；不能识别所有未知格式秘密、语义推断出的私人内容或任意跨来源编码。这是有限的确定性防护，不是完整DLP。确认中本买家所需的金额、地址、数量、ID和快照哈希仍保留，不把脱敏投影伪装成新的交易报价。

应用日志不记录买家原文、原异常正文；通用日志出口也清理格式化参数和异常栈中的已知凭据。Trace使用已有允许字段和内容计数字段，技术标签同样过滤凭据。日志仍需作为敏感运维数据限制访问。

### 保留和历史数据

本应用默认输出stdout，不自行建立无限增长的业务日志文件。部署基线要求stdout/代理日志按7天保留、单容器总量不超过100MiB，追踪服务按7天保留；由实际部署的日志驱动/收集器执行并在M6核验，当前源码测试不等于该配置已经生效。临时mock数据在退出时清理；工程验收日志/指纹作为合成证据单独保存，不写真实买家内容。

旧journal/AgentState/交易库不是可随意删除的日志。读侧防护不会销毁历史数据库；若真实凭据曾写入旧库，先停止公开访问、限制文件权限、撤销相关凭据，再以一致性备份设计审计迁移。不能为通过扫描删除失败证据、重置库存或破坏订单记录。数据保留期限涉及业务/用户决定，不能由日志TTL顺带删除交易台账。

## prepare 和 resolve 的幂等范围

新网页create/cancel准备请求都有稳定 `request_id`，作用域为买家＋会话＋操作；同键同规范商品/SKU/数量/地址（取消为订单/原因）返回同一确认，同键不同内容409。请求摘要不绑定本次价格/库存，重放先于重新报价，映射与确认同一SQLite事务提交。已过期、已批准、已拒绝的旧键仍取回原状态，不产生新授权。

“重新核验”或“再次准备”是明确的新尝试，新键产生新的报价与确认。网络失败、响应丢失和刷新复用原尝试；有Web Locks时跨标签同步创建键。缺浏览器存储或锁时界面给出限制，不能把内存互斥说成跨刷新/标签保证。

兼容旧HTTP和模型工具调用时，缺 `request_id` 仍每次生成新operation；这一兼容路径没有prepare请求去重保证。所有resolve仍使用既有确认ID＋snapshot_hash原子幂等，不会重复扣/补库存。prepare不预留库存；实际确认时价格/币种/库存变化仍会拒绝，要求重新展示确认。

新增请求映射表是版本化增量迁移，不改变旧确认哈希、已有订单和库存。不知道旧请求的客户端键，不能从载荷猜测补填。回滚旧版本前停止写请求：旧版本会忽略新增表，失去新入口的请求幂等保证；不要删除映射表或重建卷。

## 离线秘密扫描

每次CI对已跟踪文件运行 `python -m scripts.ci.secret_scan`，匹配少量高置信度供应商token、GitHub/AWS凭据和私钥头，也拒绝前端源码读取编译时共享token。报告只含文件、行号和规则，不回显命中值。扫描通过不证明不存在任意密码、未知供应商格式或未跟踪文件中的秘密；真实秘密应由部署Secret管理。
